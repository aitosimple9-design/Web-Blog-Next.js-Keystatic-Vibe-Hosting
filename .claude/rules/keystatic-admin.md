# Riêng cho Keystatic (trước đây: CLAUDE.md mục 8)
- Giữ `keystatic.config.ts` khớp 100% với mục 5 (tên trường, kiểu dữ liệu, thư mục). Ngoại lệ duy nhất: Keystatic lấy `slug` từ TÊN FILE và không ghi `slug:` vào frontmatter nên `slug` khai báo `fields.ignored()`; `posts.ts` dùng tên file khi thiếu `slug:` (có thì phải trùng). Bài do Keystatic lưu có thể không có dòng `slug:`.
- Xóa bài / chủ đề / sách trong chế độ local: `src/app/api/keystatic/[...params]/route.ts` + `src/cms/lib/content-cleanup.ts` xóa luôn thư mục ảnh cùng slug (Keystatic tự nó để lại ảnh mồ côi). Chế độ GitHub không chen được vào lệnh xóa → chạy `npm run prune-images`.
- Nút "Xem trước" trong form bài (`previewUrl` ở `keystatic.config.ts`) mở `/xem-truoc/bai-viet/<slug>`: giao diện thật của bản ĐÃ LƯU, gồm cả bài nháp và bài lên lịch (có thanh ghi chú ở đáy). Keystatic không xem được chữ đang gõ mà chưa Lưu. Trang này CHỈ quản trị viên mở được (`src/cms/lib/admin-access.ts`: chế độ local trên máy không có `VERCEL`, hoặc chế độ GitHub với người đã đăng nhập Keystatic và có quyền push vào repo), người khác nhận 404; không dựng sẵn, `noindex`, `robots.txt` chặn `/xem-truoc/`. Chế độ GitHub (web thật) đọc bản đã lưu ở nhánh `?branch=` qua GitHub API bằng token của chính người xem; chủ đề của bài lấy từ bản build, hoặc từ chính nhánh nếu mới tạo (`registerPreviewTopic`, chỉ sống trong một yêu cầu). Hộp điểm SEO và `/api/diem-seo?slug=&branch=` cũng chấm bản ở nhánh. Mọi script của giao diện quản trị phải nhận địa chỉ có `/branch/<nhánh>/` của chế độ GitHub (từng sót ở SeoPanel) **Cách xác thực quản trị viên (Lộc duyệt 2026-10-19):** cookie `keystatic-gh-access-token` do Keystatic cấp + hỏi GitHub `GET /repos/<repo>` có `permissions.push` (nhớ 60 giây, chỉ lưu bản băm); token chỉ dùng phía server, không log, không trả ra ngoài. Nút "Tạo chuyển hướng" ở chế độ GitHub commit vào NHÁNH đang soạn (`src/cms/lib/github-content.ts`); nhánh chính được bảo vệ thì GitHub từ chối và giao diện báo tạo nhánh mới (New branch).
- **NGUYÊN TẮC ĐỒNG BỘ VỚI TRANG QUẢN TRỊ (Lộc, 2026-10-16):** thêm hay xóa gì thì file đi kèm phải đồng bộ với Keystatic. Xóa trong admin → mọi file liên quan mất theo (file nội dung, thư mục ảnh theo slug, ảnh đã thay / gỡ, ảnh của singleton ở `public/images/site/`), không để ảnh mồ côi. Thêm → phải hiện ra và sửa được trong admin: KHÔNG để chữ, ảnh, liên kết, danh sách hiển thị trên web mà chỉ sửa được trong mã (việc đưa phần còn lại vào admin nằm ở kế hoạch 5 PR trong `docs/HANDOFF.md`). Luật dọn ảnh nằm MỘT nơi: `src/cms/lib/content-cleanup.ts` (`IMAGE_RULES`, `SINGLETON_IMAGE_RULES`); route API, `npm run prune-images` và `npm run check-content` đều đọc từ đó. Thêm ô ảnh mới vào `keystatic.config.ts` (thư mục `directory` mới) hoặc collection / singleton mới thì PHẢI khai báo luật dọn ảnh và thêm vào `ui.navigation`; `tests/unit/project/admin-sync.test.ts` làm hỏng build nếu quên. Trước khi mở PR có đụng admin / `content/` / `public/images/`: chạy subagent `admin-sync-reviewer`.
- **Ô chọn có nút "Thêm mới" (Lộc yêu cầu 2026-10-30):** ba ô trong form là ô tùy biến dùng chung `EntryPicker.tsx` (`src/cms/ui/entry-fields.tsx`: `bookField`, `topicField`, `subtopicsField`): "Tên sách" (khối Nguồn sách), "Chủ đề" và "Chủ đề con" của bài, và "Chủ đề" của chủ đề con. Danh sách chọn có ô tìm kiếm lấy từ mục tương ứng, cuối danh sách có "+ Thêm … mới" mở hộp thoại kiểu YouTube (Sách: tên; Chủ đề: tên, mô tả, thứ tự; Chủ đề con: thêm ô chọn Chủ đề; ảnh thêm sau ở mục riêng); tạo xong tự chọn. Ô "Chủ đề con" CHỈ hiện chủ đề con thuộc chủ đề đang chọn ở ô "Chủ đề" (ô Chủ đề báo slug qua kênh `publishTopic` / `useCurrentTopic` trong `EntryPicker.tsx` vì ô tùy biến không thấy ô bên cạnh; mục đã chọn mà lệch chủ đề vẫn hiện để bỏ chọn, kèm dòng cảnh báo đỏ; hộp "Thêm chủ đề con mới" chọn sẵn chủ đề đó). Lớp chặn thật vẫn là `check-content` ở CI. Giá trị lưu GIỐNG HỆT ô cũ (Sách = TÊN chữ, Chủ đề = slug, Chủ đề con = danh sách slug) nên cấu trúc bài không đổi; ô Tác giả vẫn gõ tay, không tự điền. Danh sách và tạo đi qua `/api/danh-muc` (`src/cms/lib/entry-store.ts`; chế độ local ghi `content/<mục>/<slug>.json`, chế độ GitHub commit vào nhánh đang soạn). `entry-fields.tsx` KHÔNG được có "use client" (config cũng chạy phía server). Ô tùy biến không có `description` riêng nên nhãn giữ ngắn. Test: `tests/unit/cms/entry-store.test.ts`, `tests/e2e/admin/book-picker.spec.ts`.
- **Cảnh báo trước khi xóa (rà soát admin 2026-11-01):** `src/cms/ui/KeystaticDeleteGuard.tsx` chèn một dòng cảnh báo vào hộp "Delete entry" của Keystatic ở trang sửa Chủ đề / Chủ đề con / Sách khi mục đang được dùng (số bài, số chủ đề con, số bìa ở Tủ sách Trang chủ). Câu soạn bằng hàm thuần `src/cms/lib/delete-usage.ts`, số liệu từ `/api/thong-ke` (`getAdminStats`: thêm `books`, `shelf`). CHỈ cảnh báo, không chặn: chế độ GitHub số liệu là bản đã merge (câu cảnh báo ghi chú điều này). Test: `tests/unit/cms/delete-usage.test.ts`, `tests/e2e/admin/delete-guard.spec.ts` (mở hộp rồi Cancel).
- **Kiểm tra nội dung ngay trong admin (Lộc chọn 2026-11-02):** `/api/kiem-tra?branch=` chạy CÙNG bộ luật với `npm run check-content` / CI (`src/shared/content-check.ts`; nguồn ổ đĩa / git ở `src/shared/content-check-node.ts`, dùng chung với script). Chế độ GitHub: đọc cả nhánh bằng `readBranchContent` (`src/cms/lib/github-content.ts`: cây file 1 lần gọi + nội dung `content/**/*.md|json` theo mã băm, nhớ giữa các lần gọi; đo thật ~2,8 giây lần đầu cho 59 file), bản gốc để so slug = bản build trên máy chủ (bản đã merge vào main), không kiểm tra ảnh mồ côi. Chế độ local: đọc thư mục dự án, bản gốc = `main` qua git, có ảnh mồ côi. Trên Vercel mà thiếu nhánh thì 400. Cùng cổng quản trị viên (404 với người khác). Máy chủ GitHub giả (`tests/e2e/admin-github/mock-github.mjs`) có `git/trees` + `git/blobs`, nhánh `nhanh-thu` có một bài lỗi để test. **Thẻ "Kiểm tra nội dung"** (`src/cms/ui/KeystaticContentCheck.tsx`) chèn ngay trước `<section>` đầu tiên của Dashboard (`/keystatic`, `/keystatic/branch/<nhánh>`): tự chạy khi mở Dashboard (chỉ sau khi Dashboard vẽ xong; nhận 404 thì chờ 1,5 giây thử lại tối đa 2 lần vì lúc vừa tải trang Keystatic có thể còn đang làm mới phiên GitHub, đã gặp thật trên Vercel) + nút "Kiểm tra lại" (không tự chạy sau mỗi lần Lưu); Đạt / Chưa đạt, lỗi nhóm theo mục với tên dễ đọc ("Bài viết · slug") và liên kết mở trang sửa (`src/cms/lib/check-links.ts`, bảng singleton phải khớp keystatic.config.ts — test chặn lệch), cảnh báo / thông tin gấp trong `<details>`. Test: `tests/unit/cms/check-links.test.ts`, `tests/e2e/admin/kiem-tra.spec.ts`.
